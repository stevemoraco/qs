# Repository Instructions

- When the user asks to commit and push, commit on the current branch unless they explicitly ask for a new branch, worktree, or pull request.
- Do not create local branches or worktrees for commit/push requests without explicit user approval.
- If a temporary branch is accidentally created, move the requested commit back to the original branch and delete the temporary branch before reporting completion.
- **Never start, stop, restart, kill, or replace Replit-managed server/PWA processes unless the user explicitly asks for that exact process action in the current message.** Do not run long-lived API servers, Vite dev/preview servers, Expo servers, mockup servers, `pnpm run replit:latest`, or any command that binds the app ports. Do not "verify" by taking over ports `8080`, `5173`, `22333`, `18115`, or related Replit app ports. Let Replit own process lifecycle and ports. Prefer static checks, unit/smoke scripts that do not bind shared app ports, code inspection, and short-lived tests on isolated ephemeral ports only when necessary.
- If an agent accidentally starts any long-lived server/PWA/test process, stop only the process it started and clearly report it. Do not clean up or restart unrelated Replit-managed processes.
- Runtime release/version labels should be generated from the release commit or server boot metadata in Mountain Time, not hardcoded in application UI. Use the format `vYYYY.MM.DD.hh.mmAM/PM.MDT` or `vYYYY.MM.DD.hh.mmAM/PM.MST`, for example `v2026.05.17.09.23AM.MDT`.
- When the user asks whether Replit is serving the latest PWA, do not start or restart servers. Inspect code, build artifacts, and Replit configuration only, then ask the user to use the Replit Run button if a process restart is needed.
- Do not rely on a previously built `artifacts/web/dist/public` bundle after committing. The web version badge embeds `__QS_CLIENT_COMMIT__` at Vite build time, so any commit after `pnpm --filter @workspace/web run build` requires another build before serving the PWA.
- **Never commit anything under `.github/workflows/`.** The Replit ↔ GitHub OAuth integration that powers both the Replit UI git sync *and* Codex's git sync does not hold the `workflow` scope, so any push containing a commit that adds or modifies a file under `.github/workflows/` is rejected by GitHub with `refusing to allow an OAuth App to create or update workflow ... without workflow scope`. A single such commit blocks **every** subsequent push — the Replit "Push to GitHub" button silently fails, `git push` from Codex fails, and the branch falls further behind on each new local commit. The directory is listed in `.gitignore`; if it reappears in `git status`, an agent re-added it and must remove it before committing. If a workflow-touching commit has already landed locally and is blocking push, rewrite history to strip `.github/workflows/` from the affected commits (`git filter-branch --index-filter 'git rm --cached -rf --ignore-unmatch .github/workflows' origin/main..HEAD`) before pushing; do not try to "fix" the auth from inside the Repl. GitHub Actions workflow files must be authored directly on github.com (or via a personal token that holds the `workflow` scope) — never from inside Replit/Codex.
